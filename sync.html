GitHub 데이터 연동 가이드

폰과 PC 에서 같은 목록을 보는 방법 · 선택 기능 · 무료

먼저 — 이 기능은 없어도 됩니다

술술다이어리의 기본 사용 방식은 기기 저장 + JSON 백업입니다. 한 대의 폰에서만 쓴다면 이 문서는 읽지 않아도 됩니다. 설정(⚙) → 전체 백업 (JSON) 을 가끔 받아 두는 것으로 충분합니다.

이 문서는 폰과 PC 를 자동으로 맞추고 싶은 분을 위한 것입니다.

1. 어떤 방식인지

제작자의 서버는 없습니다. 대신 이용자 본인의 GitHub 비공개 저장소에 기록을 파일 하나로 올려 두고, 기기들이 그 파일을 읽고 씁니다.

기본 (JSON 백업)GitHub 동기화
비용없음없음 (GitHub 무료 계정)
기기 간 자동 반영수동으로 파일 옮김자동
준비 작업없음저장소 1개 + 토큰 발급
데이터를 보는 사람나만나만 (비공개 저장소)
기기 분실 시백업 파일로 복원새 기기에서 바로 복원
저장소는 반드시 비공개(Private)로 만드세요

공개(Public)로 만들면 구매가·구매처·시음 기록·사진이 전부 인터넷에 공개되고 검색에 노출됩니다. 나중에 비공개로 바꿔도 이미 공개된 이력은 남습니다. 저장소를 만들 때 Private 을 반드시 확인하세요.

2. 설정 순서

  1. GitHub 계정을 만듭니다 github.com/signup — 무료입니다. 이미 있으면 넘어갑니다.
  2. 데이터를 담을 비공개 저장소를 만듭니다 github.com/new 에서:
    • Repository name — 예: whisky-data
    • Private 을 선택합니다 (중요)
    • 나머지는 그대로 두고 Create repository
    비어 있어도 괜찮습니다. 앱이 첫 동기화에서 파일을 만듭니다.
  3. 접근 토큰(Fine-grained PAT)을 발급합니다 Settings → Developer settings → Personal access tokens → Fine-grained tokens
    • Token name — 예: sulsul-diary
    • Expiration — 만료일을 정합니다. 만료되면 다시 발급해 앱에 넣으면 됩니다.
    • Repository access → Only select repositories → 2단계에서 만든 저장소만 선택합니다.
    • Permissions → Repository permissions → Contents 를 찾아 Read and write 로 설정합니다.
    • Generate token → 화면에 한 번만 보이는 토큰 (github_pat_…)을 복사합니다.
  4. 앱에 입력합니다 설정(⚙) → 기기 간 동기화:
    • 데이터 저장소 — 내아이디/whisky-data
    • 파일 경로 — collection.json (그대로 두면 됩니다)
    • 브랜치 — main
    • 토큰 — 복사한 토큰을 붙여 넣습니다
  5. 연결을 확인합니다 연결 진단 을 눌러 토큰과 저장소 접근이 모두 통과하는지 봅니다. 통과하면 지금 동기화 를 누릅니다.
  6. 다른 기기에서 같은 값을 넣습니다 폰과 PC 에 같은 저장소·경로·브랜치·토큰을 넣으면 목록이 합쳐집니다. 토큰은 기기마다 따로 발급해도 됩니다.
Contents 입니다 — Administration 이 아닙니다

권한에서 Administration 을 주면 파일을 읽고 쓸 수 없어 403 Resource not accessible by personal access token 이 납니다. 필요한 것은 Contents: Read and write 하나입니다.

목록에 Contents 가 보이지 않으면 + Add permissions 를 눌러 펼치세요. 처음에는 일부 권한이 접혀 있습니다.

3. 언제 동기화되나요

정해진 세 시점에만 통신합니다. 주기적인 자동 동기화는 없습니다 — 배터리와 데이터를 쓰지 않기 위해 일부러 넣지 않았습니다.

  • 앱을 열 때
  • 추가·편집·삭제 후 약 1.5초 뒤 (연속 편집은 묶어서 한 번만)
  • 지금 동기화 버튼을 눌렀을 때

앱을 벗어날 때 올리지 못한 변경이 남아 있으면 그 시점에 밀어냅니다. 헤더의 ⚙ 위에 작은 점으로 상태가 표시됩니다 — 노란색은 진행 중, 초록색은 완료, 빨간색은 실패입니다.

두 기기에서 같이 고치면 어떻게 되나요

병 단위로 더 최근에 고친 쪽이 남습니다. 삭제도 기록으로 남기므로 한쪽에서 지운 병이 다른 쪽에서 되살아나지 않습니다.

두 기기가 동시에 올려서 충돌하면 앱이 다시 읽어 합친 뒤 재시도합니다 (최대 3회). 이때 "다른 기기와 겹쳐 재시도" 안내가 보이는 것은 정상입니다.

4. 안전에 관해

  • 토큰은 이 기기의 브라우저에만 저장되며 제작자에게 전송되지 않습니다. 앱에는 서버가 없어 보낼 곳 자체가 없습니다.
  • 토큰은 암호화되지 않습니다. 기기나 브라우저 프로필에 접근할 수 있는 사람은 읽을 수 있으므로 공용 PC 에서는 켜지 마세요.
  • 토큰은 JSON·CSV 백업 파일에 포함되지 않습니다. 백업을 남에게 보내도 토큰은 새지 않습니다.
  • 권한은 그 저장소의 Contents 하나로 제한하세요. 다른 저장소나 계정 설정에는 손댈 수 없게 됩니다.
  • 기기를 잃어버렸거나 토큰이 새어 나갔다고 판단되면 GitHub 토큰 목록에서 즉시 폐기(Revoke)하고 새로 발급하세요. 폐기하면 그 토큰은 바로 무효가 됩니다.

5. 문제 해결

표시되는 오류원인과 해결
토큰이 무효합니다
401 Bad credentials		 토큰이 잘못됐거나 만료됐습니다. 앞뒤 공백이 섞이지 않았는지 확인하고, 만료됐다면 새로 발급하세요.
토큰에 이 저장소 권한이 없습니다
403		 권한이 Contents: Read and write 인지 확인하세요. Administration 을 준 경우 이 오류가 납니다. Repository access 에 그 저장소가 포함됐는지도 확인합니다.
저장소·브랜치를 확인하세요
404 Not Found		 저장소 이름 오타, 또는 브랜치가 main 이 아닌 경우입니다 (master 인 저장소도 있습니다). 대소문자도 확인하세요.
원격 파일에 items 배열이 없습니다 파일 경로가 다른 파일을 가리키고 있습니다. 경로를 collection.json 으로 되돌리세요.
다른 기기가 계속 먼저 올리고 있습니다 양쪽에서 동시에 편집 중일 때 드물게 납니다. 한쪽을 잠시 닫고 지금 동기화 를 누르세요.
데이터가 N MB 입니다 오류가 아닌 안내입니다. 사진이 많으면 동기화가 느려집니다. 사진은 병당 5장까지이므로, 필요 없는 추가 사진을 줄이면 가벼워집니다.

동기화를 끄고 싶으면

설정에서 토큰을 지우면 즉시 멈추고 기기 저장만 남습니다. 저장소의 파일은 그대로 남아 있으니, GitHub 에서 직접 지우고 토큰도 폐기하세요.
